# sharpen — 把一句話變成可執行的工作簡報

> 位置：工作流程 ① Input 與 ② 分析・Plan 之間。

## 目的
使用者常常只說一句話。直接開工的話，我會自己補假設，補錯了就要退回（③→①）。
開工前先把那句話整理成簡報：
- **分開「你說的」和「我推的」**，交給你確認。
- **做深，不做大**：不加產出，而是找最原始的素材、對的方法、驗收的方式。
sharpen 決定「做什麼」；簡報最後一行交棒給 playbook，由 playbook 決定「怎麼做」。

## 什麼時候跑
自動跑，只限兩種：
- **含糊**：只有一兩句、用詞含糊（「看一下」「處理」「更新一下」），或產出、範圍、格式不明。
- **跨階段**：同時要做兩個以上階段的事（例：「更新 X 的進度」= 查現況 + 做簡報 + 改 todo）。單純「讀一份檔、產一份東西」且輸入產出都明確的，不算。
- 使用者明確叫 sharpen 時一定跑。

不跑：
- 只查不寫的狀態查詢（例：「X 到哪了？」只要在 chat 回答）→ 直接走對應的 playbook。
- 明確的單一任務，輸入和產出都清楚（例：「列出我有哪些 todo」）。
- 純問答、查資料；使用者說「直接做」。
- 不跑時不要為了走流程而發問。

## 步驟
1. **先讀，不要先問。** 讀取順序依 playbooks 檔（見「Playbook 設定」）的「共用規則」（外部來源優先）；沒設定 playbooks 時，先讀本機檔案，再查外部來源。
   - 沒查的外部來源寫「外部未查：<原因>」，不能裝作查過。
   - 本機**完全沒有記錄**時明寫「本機無記錄」，並在假設裡提議新增追蹤項目。
   - **先找既有產出**：同主題是否已經做過（output/、portfolio、todo）。有的話當基礎，不重做。
   - **核對請求裡的事實**：使用者說的日期、版本、「新收到」等，和檔案證據（修改日、內文版本、hash）對不上時，寫進問題。
   - **格式來源**：使用者有沒有指定格式或範本（template/、既有同類產出）。沒有就用我提議的格式，在簡報寫明。
   - 需要下載的原始素材（Jira 附件、Teams 檔案）先不下載，列在簡報裡，確認簡報時一起問。
2. **自己先回答四題**（做深，不擴大），寫進「做深」欄，**最多三行**：
   - 頂尖的人會多做什麼？（例：比對 spec 版本、看 schedule 和 cost 影響、找出還沒收斂的分歧）
   - 最原始的素材是什麼？（原始量測、Jira 原票與附件、廠商原始回覆、spec 原檔）
   - 用什麼方法和工具？（例：時間軸、對照表、Cpk、python 分析）
   - 除了你和我，什麼能證明結果是對的？→ 寫進「驗收」欄。
3. **寫簡報**（格式見下）。不知道的欄位寫 unknown。
4. **問題最多三個**，只問會改變做法的。四題答不出來的缺口才變成問題，其他寫進「我先假設」。
   - 事實（Jira、Teams、mail、檔案查得到的）先自己查，不拿來問。只有偏好、取捨、對外措辭、決策才問。
   - 每個問題後面附一句「我查過：…」，寫查了哪裡、為什麼還是不知道。
5. **停下，等使用者確認或修改。** 確認前不開工，也不產出檔案（讀取不算開工）。
6. 太含糊、問題超過三個，或範圍一直在改時，改用 grill-me。
7. 確認後，簡報就是 ② 的起點：
   - 讀「Playbook」那一行對應的那一節，照 playbooks「怎麼用」的規則把步驟抄成 todo。
   - playbook 裡已被簡報答掉的步驟標「已由簡報完成」，不再重問。

## 簡報格式
```
## 工作簡報
- 你說的：<原句，一字不改>
- 為何跑 sharpen：含糊 / 跨階段 / 使用者指定
- 目標：<一句話，這次做完要得到什麼>
- 類型：計畫性 / 變更 / 突發
- 範圍：含 … ；不含 …
- 輸入與版本：<檔名、版本、日期；缺的寫 unknown；本機沒有就寫「本機無記錄」>
  - 外部來源：<查了什麼、查到哪天；沒查寫原因>
  - 既有產出：<同主題已做過的檔案；沒有寫「無」>
  - 想下載的附件：<檔名、來源；確認時一起同意>
- 做深（最多三行）：多做的一步 … ；原始素材 … ；方法／工具 …
- 產出：<格式（來源：你指定 / 既有範本 / 我提議）、檔名規則（_vN）、存放位置、給誰看>
- 驗收：<除了你我之外，什麼能證明是對的>
- 誰做：你 / 我 / 一起
- 我先假設（你說 ok 就照這個走）：1. …
- 要問你（最多三個）：1. …
- 階段：現在 ①–④ → 要做到 ①–④
- Playbook：<playbooks 索引中的一節> / 無（原因：…）
- 臨時步驟（Playbook 為「無」時才寫）：1. … 2. …（標出哪步是 ◆）
```

## Playbook 設定
- playbooks 的位置寫在使用者的 CLAUDE.md，例如一行 `sharpen playbooks: <資料夾路徑>`。讀該資料夾裡 `playbooks_vN.md` 中 N 最大的那份。
- 沒有設定，或找不到檔案：跳過「共用規則」，Playbook 欄寫「無（未設定 playbooks）」，照下方「無」的做法附臨時步驟。

## Playbook 路由
- 依 playbooks 檔的「索引」選**一節**。何時用以該檔為準，這裡不重複。
- 符合兩節時：**主要產出決定走哪節**；另一節的格式可以借用（例：狀態更新借異常處理的報告欄位），寫進「我先假設」。
- **無**：寫「無」並附原因，在簡報的「臨時步驟」欄草擬這次的步驟（編號、哪步是 ◆、預計產出）。使用者確認簡報時一起核可臨時步驟，之後照做，邊做邊修並註明修改處。同類工作第二次出現時，提議在 playbooks 加一節。

## 簡報放哪
- **預設留在 chat**，不寫檔。
- 工作會跨 session 時，直接寫入、寫完再告知，不先問：
  - 專案有 `_context/on-demand/tickets.md` → 寫進對應 ticket 的一節，說「(noted to tickets: <ID>)」。
  - 專案沒有 tickets.md → 摘要記在 journal.md，說「(noted to journal)」。**不自己新建 tickets.md**。
  - todo.md 只留指向（單一來源）。

## 工作區外的專案
- 專案在工作區外（例：放在另一個磁碟的客戶專案資料夾）時，產出預設放**該專案自己的 output/**，追蹤檔遵循**該專案的 claude.md**（例：`.context/` 而非 `_context/`）。
- 簡報的「產出」欄寫明存放位置；使用者沒指定時列為問題。

## 多個 pane 同時工作
- 瀏覽器：開自己的分頁，用完關掉，不動別的分頁。
- 追蹤檔：寫入前重讀一次；另一個 pane 正在改同一個專案的檔案時，先告訴使用者再寫。

## 規則
- 「你說的」之外每一項都要標依據：實測（讀到的原始資料，附出處）／推論（附根據）／猜測（沒有直接依據）。不能把推論或猜測寫得像事實。
- 日期用環境當天的日期。
- **退回、作廢、階段移動只能提案**：寫成「建議退回 ②，原因：<五類之一>」，由你確認。
- 不寄送，不發佈，只產出簡報。

## 範例（虛構案例）
使用者說：「請更新專案 A 外殼裂紋的最新進度」
```
## 工作簡報
- 你說的：請更新專案 A 外殼裂紋的最新進度
- 為何跑 sharpen：含糊（「更新」是回報還是寫檔？）+ 跨階段（本機無記錄，要新增追蹤）
- 目標：整理 ABC-123 到今天的現況與下一步，知道球在誰手上
- 類型：突發（試產異常，已在對策驗證）
- 範圍：含對策進度、驗證結果、客戶最新要求；不含重新分析根因
- 輸入與版本：本機無記錄
  - 外部來源：Jira ABC-123 描述 + 10 則留言（到昨天）；Teams 群組（最後訊息兩週前）
  - 既有產出：無
  - 想下載的附件：Housing_Validation_v3.pptx（Jira）
- 做深：兩條根因線（設計餘裕 vs 材料）未收斂，看改模對量產的影響；原始素材 供應商最新驗證報告；方法 時間軸 + 對策對照表
- 產出：未定（問題 1）
- 驗收：每個日期和數字都能對回 Jira 或 Teams 原文
- 誰做：我
- 我先假設：1. 指 ABC-123，不含相關的 ABC-122。2. 格式借「異常處理」的報告欄位。3. 建議新增追蹤項目。
- 要問你：1. 產出只要 chat 摘要，還是加簡報／本機追蹤？2. 客戶最新的測試要求要不要列為待決？
- 階段：現在 ① → 要做到 ④
- Playbook：狀態更新
```
